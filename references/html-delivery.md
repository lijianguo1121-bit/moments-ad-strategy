# HTML 交付页 与 后台配图

> 客户拿到的是**能直接双击打开的网页**，不是一堆 .md 文件。方案、文案、效果图、配图应该装在一个自包含 HTML 里，顺手就能发给别人；后台配图则是要上传到投放后台的成品素材图。

## 一、HTML 交付页（主交付物）

用 `scripts/build_report_html.py` 组装一个自包含 HTML（图片内嵌 base64，无外部依赖、无网络请求）：

```bash
python3 <skill目录>/scripts/build_report_html.py --config build.json
```

### 页面结构

| 区块 | 内容 |
| --- | --- |
| 顶部 Hero | 品牌 + 标题 + 关键数字（文案条数 / 效果图数 / 必拒审 0 / 计划数） |
| 一、概览 | 这份交付里有什么 + 投放前必读 |
| 二、可投放文案 | 10 条卡片，带「复制文案 / 复制大字 / 复制这一条全部」按钮 + 顶部「复制全部」 |
| 三、详情页配图文案 | **5 套**详情页文案（钩子复述 + 主视觉 + 补充行 + 3 条卖点），每套带复制按钮 + 「复制全部 5 套」 |
| 四、广告效果图 | 朋友圈卡片效果图（**最多 2 张**：每个投放计划 1 张），点图放大（灯箱） |
| 五、后台配图 | 横版 16:9 详情页首屏配图 × 2（A/B）+ 竖版 9:16 钩子海报 × 2（A/B），带规格表 |
| 六、详情页（落地页） | 竖版长页整页长图（可滚动查看）+ 规格表；另有可发布的 `landing/详情页.html` |
| 五、投放策略方案 | 方案 Markdown 全文（左侧导航按 h2 自动生成锚点） |
| 六、合规审核报告 | 审核结论、改写对照、资质清单 |
| 交付清单 | 文件清单 + 上线前 checklist |

左侧固定导航自动从两份 Markdown 的 h2 标题生成锚点，长文档也能跳着看。
样式带 `@media print`，可直接浏览器打印成 PDF。

### build.json

```json
{
  "title": "朋友圈广告投放策略方案",
  "brand": "IMAI · AI 投放营销",
  "out": "/abs/path/交付页.html",
  "docs": [
    {"key": "plan",  "label": "投放策略方案", "path": "投放策略方案-XXX.md"},
    {"key": "audit", "label": "合规审核报告", "path": "合规审核报告-XXX.md"}
  ],

  "detail_spec": "detail_copy_spec.json",
  "assets": [

```

依赖：`markdown`（pip 安装）、`Pillow`、`playwright`（仅验证时用）。

## 二、后台配图（每个版式最多 2 张）

投放后台要备两种版式的图，**每个版式最多 2 张（A/B 两版）**，别多做——效果图/配图是"确认方向"用的，2 张足够。

| | 横版 **16:9** | 竖版 **9:16** |
| --- | --- | --- |
| 尺寸 | 1920 × 1080（可无损缩至 1280 × 720） | 1080 × 1920 |
| 定位 | **详情页（落地页）首屏配图** | **钩子海报**（私聊/群发引流、沉浸式大图位） |
| 构图 | 左侧文字区 + 右侧人像，单向渐变遮罩 | 顶部痛点钩子 → 中部主视觉 → 卖点 → 底部人设收口 |
| 识读顺序 | 人设 → 钩子复述 → 主利益 → 三个卖点 → 信任条 | 一屏从上读到下：钩子 → 价格/承诺 → 卖点 → 收口 |

### 详情页文案给 5 套，且必须可复制

成品图每个版式最多 2 张，但**详情页的文字要成套给 5 套**——客户要拿它去改图、给设计、做 A/B，只有 2 套不够用。每套的结构固定：

```
钩子复述：<与广告外层同一件事，一句提问>
主视觉：<最硬的那句利益/承诺>
补充行：<规则或补充说明>
卖点1 / 卖点2 / 卖点3      <- 每条 ≤10 字
```

- 写成 `detail_copy_spec.json`（结构与 `copy_spec.json` 相同），交付页里单独成节，每套一个「复制这一套」按钮 + 一个「复制全部 5 套」
- 5 套按**不同人群/痛点**分（获客成本焦虑 / 存量会员沉睡 / 被投流师劝退 / 老客不复购 / 怕烧钱停不下来），不要只是换同义词
- 词表用 **`--mode page`** 扫（详情页是网页，不受 40 字与空格限制）
- 要把某一套落成成品图：改 `build_ad_assets.py` 里 `VARIANTS` 的 `hook / big / rule / points`，**复用同一张背景图，零额外积分**

### 详情页的文生图提示词也要给（可复制）

详情页的图（首屏人物图、行业格子图、块图标）**必须同时交一份「文生图提示词清单」**——企业要自己换图、自己重生成，只给成品图等于没交付。清单按分组给，每条一个复制按钮：

| 分组 | 内容 | 要点 |
| --- | --- | --- |
| ① 首屏 · 痛点人物图 | 1 条完整提示词 | 人物必须**居中**（4 张痛点气泡会压左右两侧），四周留够空间 |
| ② 行业覆盖格子图 | **1 条模板 + N 个行业变量** | 12 格只用一套模板、只换场景描述，风格才统一 |
| ③ 能力块 / 理由块图标 | 1 条模板 + 每个图标一句图形描述 | 固定主色与"纯白背景、图形居中、留白充足" |

**五条通用规范（写进清单开头）**：

1. 提示词里**不要要求生成中文文字**——AI 生成的中文不可靠，页面文字统一用 HTML/CSS 叠加
2. 图片只当背景：留出文字区、避免高对比细节，否则叠字看不清
3. 同组图只用一套模板、只换变量，别每条重写
4. 不要出现真实品牌 logo、二维码、电话、微信号；门头/包装上的标识让 AI 虚化
5. 涉及真人出镜的正式投放，须换成企业自己拍的实景与员工照并取得肖像授权；AI 人像必须标注

实现：写一个 `landing_prompts.json`（`items[]`：group / slot / size / prompt / note，另有 `rules[]`），
`render_copy_sheet.py` **自动识别 `items` 结构**并渲染成按组分类的提示词清单页。

### 横版按"详情页首屏五元素"排布

详情页不是再放一张大海报，而是承接广告的落地第一屏，五元素一个不能少：

1. **人设条**：小头像 + 人设名 + 身份（与外层广告同一人，同头像）
2. **复述钩子**：**原广告外层第一行原样出现或换个说法说同一件事**——承诺一致性的关键一环
3. **主利益**：一句最硬的利益/证据（如"3分钱一次曝光，看到才扣"）
4. **三个卖点**：每条 ≤10 字，圆点排开
5. **信任条**：底部分隔线上，放平台/资质类可信信息（如"腾讯广告同一账户体系 · 正规开户通道"）

> ⚠️ **不要在图片里画按钮**。图片里的假按钮既属平台禁的"按钮元素"，用户点了也不会有反应——**真实按钮放在图片下方的页面里**。

### 竖版作为钩子

顶部一句痛点钩子（越短越好）→ 中部主视觉价格/承诺 → 三条卖点 → 底部人设署名 + 品牌。
竖屏必须**一屏读完**，不要指望用户滑动。

### A/B 两版怎么分

区别只放**主打人群与主视觉**，版式完全复用：

| | A 版 | B 版 |
| --- | --- | --- |
| 人群 | 中小企业老板 · 获客成本焦虑 | 实体门店老板 · 存量会员沉睡 |
| 钩子 | 广告费花了，客户一个没来？ | 店里几千个会员，还睡着？ |
| 主视觉 | 3分钱一次曝光，看到才扣 | 成交一个，停投一个 |

对应到投放计划：A 版配计划 B（中小企业），B 版配计划 A（实体店）——**别两版同时上线抢同一批人**。
两版**复用同一张背景图 → 零额外积分**。

### 做法：HTML 排版 + Playwright 截图

比 PIL 画图强得多——字号、行高、渐变、对齐全部可控，改字不用改代码逻辑：

1. 背景图先用图像生成，按目标比例裁到 16:9 / 9:16（`cover` 逻辑 + `focus` 控制裁切重心）
2. HTML 里用绝对定位铺背景 + 单向渐变遮罩（文字所在侧压暗、人像侧透亮）
3. `viewport` 精确设为目标尺寸，`device_scale_factor=1`，`screenshot(clip=...)` 出图
4. 字体用系统 CJK 栈（PingFang SC / Hiragino Sans GB），不要用细体

参考实现：见项目里的 `build_ad_assets.py`（横竖两套模板 + 裁图工具函数，直接抄改文字即可）。

### 素材合规（两条图的硬约束）

- ✕ **不放二维码、电话、微信号、URL、按钮元素** —— 平台禁止，且图片文字会被 **OCR 抓取**，谐音/艺术字/拆字同样会被识别
- ✕ 不做"大字报"；**图片文字占比压在低位**（老规范 ≤20%，近期口径 ≤30%）
- ✕ 不模仿微信系统通知、朋友圈界面、未读提示
- ✓ 数字类承诺（0.03 元/次等）与方案口径一致，并备好计费口径说明
- ⚠️ AI 生成人像必须标注；**正式投放换成真人实拍**（真人是信任核心）

## 三、详情页（落地页）长页

详情页不是"再放一张大海报"——它是**一张完整的竖版长页**，承担从"点进来的焦虑"到"留下联系方式"的全过程。结构照原生落地页模板：

| # | 区块 | 内容 |
| --- | --- | --- |
| 1 | **首屏 + 痛点** | 一句专治目标人群的钩子标题 + 副标题；**4 个痛点气泡卡围绕一张"苦恼的老板"实景图**，卡片左右交错、允许压住人物肩部 |
| 2 | **品牌区** | Logo 胶囊 + 主口号（如"让 AI 替你投广告"）+ 一句背书（腾讯广告同一账户体系）+ **4 个能力块**（1 让 AI 替你找人 / 2 替你投放 / 3 替你跟单 / 4 替你复盘） |
| 3 | **行业覆盖** | 3 列网格，12 个行业格子，同色系渐变（**不要跳色**，视觉要统一） |
| 4 | **选择理由** | 2×2 卡片：大字承诺 + 一行说明（便宜 / 精准 / 可控 / 覆盖广） |
| 5 | **留资表单** | 字段 **≤3 个**（姓名 / 手机号 / 公司名）；手机号可加"一键填写"；**授权勾选默认不勾选** |
| 6 | **底部备案** | "页面信息及服务由 XX 提供" + AI 生成素材声明（**必须加**） |

### 硬性规范

- **表单授权勾选默认不勾选**（平台要求），并要有隐私条款入口
- 表单**≤3 字段**；正式投放要接平台自带的【表单】/【商家微信】组件，别自己起一套
- 底部必须写"页面信息及服务由 XX 提供"，并留备案信息位
- ✕ 不出现二维码、电话、微信号、群二维码（教育培训类落地页还禁止出现加群内容）
- ✕ 不做效果承诺、不暗示增收
- 落地页域名需 **ICP 备案**，备案主体与广告账户一致

### 做法

`scripts/build_landing_page.py`（可复制改内容）：内容以常量数组写在文件顶部（`PAINS` / `ABILITIES` / `INDUSTRIES` / `REASONS`），
用 750px 宽（移动端 2x）排版 → Playwright `full_page=True` 出整页长图。
产出两个文件：`landing/详情页.html`（自包含，可直接打开/托管）与 `landing/详情页-长图.png`（预览/交付页内嵌）。

> 首屏那张"苦恼的老板"图用图像生成即可（每张 5–10 积分），裁掉水印后在页面底部注明"含 AI 生成示意素材"。

## 四、交付顺序

```
1. check_compliance.py  →  BLOCK 归零（外层用 outer 模式，详情页用 --mode page）
2. render_ad_mockup.py  →  效果图 × 2          （最多 2 张，确认方向）
3. render_copy_sheet.py →  文案-可复制-合规版.html（改文案用）
4. 后台配图             →  16:9 × 2 + 9:16 × 2   （详情页配图 + 钩子海报）
5. build_landing_page.py→  详情页.html + 详情页-长图.png（竖版长页落地页）
6. build_report_html.py →  交付页.html          （最终呈现，装下以上全部）
```
