# HTML 交付页 与 后台配图

> 客户拿到的是**能直接双击打开的网页**，不是一堆 .md 文件。方案、文案、效果图、配图应该装在一个自包含 HTML 里，顺手就能发给别人；后台配图则是要上传到投放后台的成品素材图。

## 一、HTML 交付页（主交付物）

用 `scripts/build_report_html.py` 组装一个自包含 HTML（图片内嵌 base64，无外部依赖、无网络请求）：

```bash
python3 <skill目录>/scripts/build_report_html.py --config build.json
```

### 页面结构

| 区块 | 内容 |
| --- | --- |
| 顶部 Hero | 品牌 + 标题 + 关键数字（文案条数 / 效果图数 / 必拒审 0 / 计划数） |
| 一、概览 | 这份交付里有什么 + 投放前必读 |
| 二、可投放文案 | 10 条卡片，带「复制文案 / 复制大字 / 复制这一条全部」按钮 + 顶部「复制全部」 |
| 三、详情页文案 | **5 套**详情页文案（钩子复述 + 主视觉 + 补充行 + 3 条卖点），每套带复制按钮 + 「复制全部」 |
| 四、海报文案 | **N 份**海报文案（大字 + 补充行 + 3 条卖点 + 收口），有 `poster_spec` 时才出现 |
| 五、广告效果图 | 朋友圈卡片效果图（**最多 2 张**：每个投放计划 1 张），点图放大（灯箱） |
| 六、后台配图 | 横版 16:9 详情页首屏配图 × 2（A/B）+ 竖版 9:16 钩子海报 × 2（A/B），带规格表 |
| 七、详情页（落地页） | **配图提示词 + 该屏文案**（2 条，都可一键复制）→ 两屏 9:16 成品图 + 规格表；另有可发布的 `landing/详情页.html` |
| 八、投放策略方案 | 方案 Markdown 全文（左侧导航按 h2 自动生成锚点） |
| 九、合规审核报告 | 审核结论、改写对照、资质清单 |
| 交付清单 | 文件清单 + 上线前 checklist（**配置驱动**：`deliverables` / `checklist` 可选，缺省自动生成，不要硬编码客户名与文件名） |

左侧固定导航自动从两份 Markdown 的 h2 标题生成锚点，长文档也能跳着看。
样式带 `@media print`，可直接浏览器打印成 PDF。

### build.json

```json
{
  "title": "朋友圈广告投放策略方案",
  "brand": "IMAI · AI 投放营销",
  "out": "/abs/path/交付页.html",
  "docs": [
    {"key": "plan",  "label": "投放策略方案", "path": "投放策略方案-XXX.md"},
    {"key": "audit", "label": "合规审核报告", "path": "合规审核报告-XXX.md"}
  ],
  "copy_spec": "copy_spec_compliant.json",
  "detail_spec": "detail_copy_spec.json",
  "poster_spec": "poster_copy_spec.json",
  "landing_prompts": "landing_prompts.json",
  "landing": {
    "images": ["landing/详情页-上屏-9x16.png", "landing/详情页-下屏-9x16.png"],
    "spec": {"形式": "两张 9:16（1080 × 1920），可上下连排"}
  },
  "assets": [
    {"title": "横版配图", "ratio": "16:9", "image": "assets/后台配图-16x9-A.png",
     "max_w": 1400, "spec": {"尺寸": "1920 × 1080", "用途": "详情页（落地页）首屏配图"},
     "note": "识读顺序：价格 → 扣费规则 → 卖点"}
  ],
  "effects": [{"image": "ad_effects/x.png", "caption": "文案 1 · …"}]
}
```

依赖：`markdown`（pip 安装）、`Pillow`、`playwright`（仅验证时用）。

## 二、后台配图（每个版式最多 2 张）

投放后台要备两种版式的图，**每个版式最多 2 张（A/B 两版）**，别多做——效果图/配图是"确认方向"用的，2 张足够。

| | 横版 **16:9** | 竖版 **9:16** |
| --- | --- | --- |
| 尺寸 | 1920 × 1080（可无损缩至 1280 × 720） | 1080 × 1920 |
| 定位 | **详情页（落地页）首屏配图** | **钩子海报**（私聊/群发引流、沉浸式大图位） |
| 构图 | 左侧文字区 + 右侧人像，单向渐变遮罩 | 顶部痛点钩子 → 中部主视觉 → 卖点 → 底部人设收口 |
| 识读顺序 | 人设 → 钩子复述 → 主利益 → 三个卖点 → 信任条 | 一屏从上读到下：钩子 → 价格/承诺 → 卖点 → 收口 |

### 详情页文案给 5 套，且必须可复制

成品图每个版式最多 2 张，但**详情页的文字要成套给 5 套**——客户要拿它去改图、给设计、做 A/B，只有 2 套不够用。每套的结构固定：

```
钩子复述：<与广告外层同一件事，一句提问>
主视觉：<最硬的那句利益/承诺>
补充行：<规则或补充说明>
卖点1 / 卖点2 / 卖点3      <- 每条 ≤10 字
```

- 写成 `detail_copy_spec.json`（结构与 `copy_spec.json` 相同），交付页里单独成节，每套一个「复制这一套」按钮 + 一个「复制全部 5 套」
- 5 套按**不同人群/痛点**分（获客成本焦虑 / 存量会员沉睡 / 被投流师劝退 / 老客不复购 / 怕烧钱停不下来），不要只是换同义词
- 词表用 **`--mode page`** 扫（详情页是网页，不受 40 字与空格限制）
- 要把某一套落成成品图：把它写进 `assets_spec.json` 的 `variants`，跑 `build_ad_assets.py --spec assets_spec.json`，**复用同一张背景图，零额外积分**

### 详情页配图提示词：**只有 2 条（一屏一条），但每条必须同时给出「这一屏要写的文案」**

详情页只做成**两张 9:16**，所以配图提示词**只给 2 条**——上屏一条、下屏一条。不要拆成十几条子元素提示词：整页就两屏，多出来的都是噪音。

| 提示词 | 生成什么 | 要点 |
| --- | --- | --- |
| **第 1 条 · 上屏** | 首屏的**视觉底**：浅蓝渐变背景 + "苦恼的老板"人物 | 人物**居中**（4 张痛点气泡会压左右两侧）；上部留大片空白给标题 |
| **第 2 条 · 下屏** | 下屏的**视觉底**：同色系极简渐变 + 少量光带 | 全是白色卡片（能力块/行业格/理由卡），背景必须更淡更干净 |

**两条提示词必须写死同一套色调**，并明确要求"下屏顶端颜色与上屏底部一致"——**前后色调呼应、能上下无缝连排**，这是两屏看起来像一整页的关键。

#### ⚠️ 每条提示词下必须附「这一屏实际要写的文案」

这是最容易漏、也最致命的一处：提示词只出**视觉底**（见规范第 3 条），页面上的字全靠排版叠上去。**只给提示词等于只交付了一半**——拿到人生成出干净背景图，却不知道该往上写什么。

所以每条要在同一个 `item` 里给 `copy` 数组，逐处列出：

| 上屏（示例） | 下屏（示例） |
| --- | --- |
| 顶部标签 / 主标题 / 副标题 | 能力块 1–4（各含标题 + 一行说明） |
| 痛点卡 1–4（各含小标题 + 一行说明） | 行业区标签 + 标题 + 12 个格子名 |
| 品牌区 Logo / 主口号 / 背书 | 理由区标签 + 标题 + 理由卡 1–4（大字 + 一行说明） |

**图与字要能分别复制**：出图的人拿 prompt、排版的人拿 copy，两者常不是同一个人。因此每条卡上挂三个按钮——`复制提示词` / `复制这一屏文案` / `复制整屏（提示词+文案）`，页面顶部再给 `复制全部 N 条提示词` 与 `复制全部落地页文案`。

**通用规范（写进清单开头）**：

1. 落地页就两张 9:16：上屏（钩子 + 痛点 + 品牌）与下屏（能力块 + 行业 + 理由），各自一条提示词，不要拆更多
2. 两屏同一套色调；下屏顶端颜色要接住上屏底部
3. 两条提示词都只要 AI 出**视觉底**（渐变 + 人物/光带），**不要要求它写中文文字、不要让它画卡片**——文字与卡片一律用 HTML/CSS 叠
4. **每条必须同时给出该屏的完整文案**（`copy[]`），否则交付不完整
5. 底图要低对比、留白多
6. 不出现真实品牌 logo、二维码、电话、微信号；涉及真人出镜的正式投放，须换成企业自己拍的实景与员工照并取得肖像授权

实现：写一个 `landing_prompts.json`（`items[]`：group / slot / size / prompt / note / **copy[]**，另有 `rules[]`），
`render_copy_sheet.py` **自动识别 `items` 结构**并渲染成"一条一卡、提示词与文案都能一键复制"的清单页；
`build_report_html.py` 的交付页会嵌同一份数据，两处表现一致。

### 横版按"详情页首屏五元素"排布

详情页不是再放一张大海报，而是承接广告的落地第一屏，五元素一个不能少：

1. **人设条**：小头像 + 人设名 + 身份（与外层广告同一人，同头像）
2. **复述钩子**：**原广告外层第一行原样出现或换个说法说同一件事**——承诺一致性的关键一环
3. **主利益**：一句最硬的利益/证据（如"3分钱一次曝光，看到才扣"）
4. **三个卖点**：每条 ≤10 字，圆点排开
5. **信任条**：底部分隔线上，放平台/资质类可信信息（如"腾讯广告同一账户体系 · 正规开户通道"）

> ⚠️ **不要在图片里画按钮**。图片里的假按钮既属平台禁的"按钮元素"，用户点了也不会有反应——**真实按钮放在图片下方的页面里**。

### 竖版作为钩子

顶部一句痛点钩子（越短越好）→ 中部主视觉价格/承诺 → 三条卖点 → 底部人设署名 + 品牌。
竖屏必须**一屏读完**，不要指望用户滑动。

### A/B 两版怎么分

区别只放**主打人群与主视觉**，版式完全复用：

| | A 版 | B 版 |
| --- | --- | --- |
| 人群 | 中小企业老板 · 获客成本焦虑 | 实体门店老板 · 存量会员沉睡 |
| 钩子 | 广告费花了，客户一个没来？ | 店里几千个会员，还睡着？ |
| 主视觉 | 3分钱一次曝光，看到才扣 | 成交一个，停投一个 |

对应到投放计划：A 版配计划 B（中小企业），B 版配计划 A（实体店）——**别两版同时上线抢同一批人**。
两版**复用同一张背景图 → 零额外积分**。

### 做法：HTML 排版 + Playwright 截图

比 PIL 画图强得多——字号、行高、渐变、对齐全部可控，改字不用改代码逻辑：

1. 背景图先用图像生成，按目标比例裁到 16:9 / 9:16（`cover` 逻辑 + `focus` 控制裁切重心）
2. HTML 里用绝对定位铺背景 + 单向渐变遮罩（文字所在侧压暗、人像侧透亮）
3. `viewport` 精确设为目标尺寸，`device_scale_factor=1`，`screenshot(clip=...)` 出图
4. 字体用系统 CJK 栈（PingFang SC / Hiragino Sans GB），不要用细体

参考实现：`scripts/build_ad_assets.py`（横竖两套模板 + 裁图工具函数 + CSS 静默失效自查）。**用 `--spec assets_spec.json` 调用，不要改脚本源码。**

`assets_spec.json` 字段：

| 位置 | 字段 |
| --- | --- |
| 顶层 | `accent`、`person`（`name`/`role`/`initial`）、`brand`、`brand_foot`、`trust[]`、`bg_wide`、`bg_tall`、`focus_wide`、`focus_tall`、`out_dir`（可选） |
| `variants.A / B` | `hook[2]`、`big[2]`、`rule`、`points[]`（3 条）、`kicker`、`tall_hook[2]`、`tall_big[2]`、`tall_small`、`tall_points[]`（3 条），可覆盖 `bg_wide`/`bg_tall` |

- `variants` **最多 2 个**（A/B）；背景图可写在顶层做默认、变体覆盖；**A/B 复用同一张 → 零额外积分**
- 输出到**当前工作目录**的 `assets/`（`--out` 可指定）；脚本自查出图尺寸必须为 1920×1080 / 1080×1920

### 素材合规（两条图的硬约束）

- ✕ **不放二维码、电话、微信号、URL、按钮元素** —— 平台禁止，且图片文字会被 **OCR 抓取**，谐音/艺术字/拆字同样会被识别
- ✕ 不做"大字报"；**图片文字占比压在低位**（老规范 ≤20%，近期口径 ≤30%）
- ✕ 不模仿微信系统通知、朋友圈界面、未读提示
- ✓ 数字类承诺（0.03 元/次等）与方案口径一致，并备好计费口径说明
- ⚠️ AI 生成人像必须标注；**正式投放换成真人实拍**（真人是信任核心）

## 三、详情页（落地页）两屏 9:16

详情页不是"再放一张大海报"，也不是一条长页——它是**两张 9:16**（1080 × 1920）的上下两屏，可连排成一整页，承担从"点进来的焦虑"到"愿意留资"的全过程：

| 屏 | 区块 | 内容 |
| --- | --- | --- |
| **上屏** | ① **首屏 + 痛点** | 一句专治目标人群的钩子标题 + 副标题；**4 个痛点气泡卡围绕一张人物实景图**，卡片左右交错、允许压住人物肩部 |
| | ② **品牌区** | Logo 胶囊 + 主口号 + 一句背书 |
| **下屏** | ③ **能力块** | 2×2，四个"替你做什么" |
| | ④ **覆盖范围** | 3 列网格，12 个格子（区域 / 服务类型），同色系渐变（**不要跳色**，视觉要统一） |
| | ⑤ **选择理由** | 2×2 卡片：大字承诺 + 一行说明 |

**两屏共用同一套浅蓝 #DCE9F7 → 白 的竖向渐变 + 暖橙点缀**，下屏顶端接住上屏底部——色调呼应才像一整页。

### 硬性规范

- 🚫 **留资表单不要做进图**——表单、隐私授权勾选、提交按钮一律走**投放后台自带的【表单】/【商家微信】组件**。理由：画进图里的输入框点不动，且和平台组件重复；平台组件才能真的收到线索、才有隐私协议与数据合规。
- 🚫 同理，"页面信息及服务由 XX 提供"、隐私条款入口这类**页面级文案放后台页面里**，不贴在图上。
- ✕ 不出现二维码、电话、微信号、群二维码（教育培训类落地页还禁止出现加群内容）
- ✕ 不做效果承诺、不暗示增收
- 落地页域名需 **ICP 备案**，备案主体与广告账户一致

### 做法

`scripts/build_landing_page.py --spec landing_spec.json`（**spec 驱动，不要改脚本源码**）：1080 × 1920 排版 → Playwright **按屏截图**（`#s1` / `#s2`）。

`landing_spec.json` 字段：

| 段 | 字段 |
| --- | --- |
| 顶层 | `accent`、`accent2`、`ink`、`page_title`、`out_dir`（可选） |
| `screen1` | `tag`、`title[2]`（前段/强调段）、`subtitle`、`pains[4]`（每项 `[标题, 说明]`）、`person_image`（**可选**，缺了自动跳过人物块）、`person_crop_bottom`（默认 1.0 不裁）、`brand_logo`、`brand_title[2]`、`brand_sub` |
| `screen2` | `abilities[4]`（`[序号, 标题, 说明]`）、`area_tag`、`area_title`、`areas[]`（推荐 12 项，3 列网格）、`reason_tag`、`reason_title`、`reasons[4]`（`[主词, 副词, 说明]`） |

`pains` / `abilities` / `reasons` **必须各 4 条**（版面按 4 张卡定位），缺了直接报错退出。

产出三个文件到**当前工作目录**的 `landing/`（`--out` 可指定）：`详情页.html`（两屏叠放，可直接打开/托管）+ `详情页-上屏-9x16.png` + `详情页-下屏-9x16.png`。脚本自查出图尺寸必须为 1080 × 1920。

⚠️ **不要靠裁图去掉人物图上的「AI 生成」标注**（`person_crop_bottom` 默认 1.0 就是为此）。用 AI 生成的人物图时保留标注，正式投放换实拍。

> 上屏那张人物图用图像生成即可（每张 5–10 积分），裁掉水印后按需可标注"含 AI 生成示意素材"。
> **改完内容一定量一次两屏是否溢出**：`pg.locator("#s1").evaluate("e=>e.scrollHeight")` 必须 ≤ 1920。

## 四、海报营销文案（用户要海报时出）

海报是另一类交付物：**文字印在图里，一屏就是一个完整信息**。建议出 **5 份**，按不同人群 / 痛点分，既能各自独立成海报，也能 A/B 铺开。

| 元素 | 要求 |
| --- | --- |
| **大字（主视觉）** | **≤10 字**——它是海报上唯一的"1 秒信息"，用户划过去只看得到它 |
| **补充行** | 承接大字、把话说圆；**不要重复大字** |
| **3 条卖点** | 每条 ≤15 字，用圆点或胶囊标签排开 |
| **收口** | 人设 + 年限 + 覆盖范围；**各份通用、换海报不换收口**——这是人设一致性的锚点 |

**额外硬规范**：

- ✕ 不放二维码、电话、微信号、URL、按钮元素（OCR 会抓，点了也没反应）
- ✕ 不做大字报，图片文字占比压低位
- 涉及**第三方品牌名**（如"摩恩"）须有品牌授权书；无授权只保留人设与本地门店表述
- 数字（30年 / 2000多户 / 8户）须能佐证；造稀缺必须真实且按期兑现
- 正式投放把 AI 示意人物换成本人实拍，并留存肖像授权书

**做法**：写成 `poster_copy_spec.json`（同样 `ads` 数组，`copy[]` 用 `大字：/ 补充行：/ 卖点1–3：/ 收口：` 做标签），
用 `render_copy_sheet.py` 出可一键复制页（spec 里可用 `rules` 放通用规范、`labels` 覆盖按钮文案）；
在 `build.json` 里加 `"poster_spec": "poster_copy_spec.json"`，交付页会多出一个「海报文案」板块。

> 要把某一份做成**成品海报**：把它写进 `assets_spec.json` 的 `variants`（`tall_hook` / `tall_big` / `tall_small` / `tall_points`），跑 `build_ad_assets.py --spec assets_spec.json`（竖版 1080×1920），**与钩子海报共用同一套版式和背景，零额外积分**。

## 五、交付顺序

```
1. check_compliance.py  →  BLOCK 归零（外层用 outer 模式，详情页/海报用 --mode page）
2. render_ad_mockup.py  →  效果图 × 2          （最多 2 张，确认方向）
3. render_copy_sheet.py →  文案-可复制-合规版.html（改文案用）
4. build_ad_assets.py --spec assets_spec.json      →  16:9 × 2 + 9:16 × 2（详情页配图 + 钩子海报）
5. build_landing_page.py --spec landing_spec.json  →  详情页两屏 9:16 + 详情页.html
6. render_copy_sheet.py →  海报文案-可复制.html （用户要海报时）
7. build_report_html.py →  交付页.html          （最终呈现，装下以上全部）
```
